All editor integrations require the Nori LSP server binary (`nori-lsp`). This page explains how to build it from source.

## Prerequisites

- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)

Verify your installation:

```bash
dotnet --version
# Should print 8.0.x or later
```

## Building

The LSP server source is in `tools~/Nori.Lsp/` within the Nori package directory. Navigate to the `tools~` directory and run:

import { Tabs, TabItem } from '@astrojs/starlight/components';

<Tabs>
  <TabItem label="Windows">
```bash
cd tools~
dotnet publish Nori.Lsp/Nori.Lsp.csproj -r win-x64 -c Release
```

Output: `Nori.Lsp/bin/Release/net8.0/win-x64/publish/nori-lsp.exe`
  </TabItem>
  <TabItem label="macOS (Intel)">

Output: `Nori.Lsp/bin/Release/net8.0/osx-x64/publish/nori-lsp`
  </TabItem>

The publish command produces a self-contained, single-file binary that includes the .NET runtime. No additional dependencies are needed on the target machine.

## Using the Unity Setup Wizard

The easiest way to build the server is from Unity:

1. Open your Unity project
2. Go to **Tools > Nori > Setup Editor...**
3. Click **Build LSP Server**

The wizard automatically detects your platform and runs the correct build command. The resulting binary path is displayed and can be copied to your clipboard.

## The extern catalog

The LSP server accepts an optional `--catalog` flag:

```bash
nori-lsp --catalog /path/to/extern-catalog.json
```

The extern catalog is a JSON file describing all VRChat SDK types, methods, properties, and enums that are available in Udon. Without it, the server uses a built-in catalog with limited API coverage (~50 common externs). With the full catalog, you get complete autocomplete and type checking for the entire VRChat API.

### Generating the catalog

In Unity:
1. Go to **Tools > Nori > Generate Extern Catalog** (or open **Project Settings > Nori** and click **Generate Catalog from VRC SDK**)
2. The catalog JSON file is saved to your project

The catalog is generated by reflecting over the VRChat SDK assemblies at editor time, so it always matches the SDK version in your project.

### Passing the catalog to your editor

Each editor has its own way of passing the `--catalog` argument to the LSP server:

- **VS Code:** Set the `nori.catalog.path` extension setting
- **Rider:** Add `--catalog /path/to/catalog.json` to the Language Server arguments
- **Visual Studio:** Add to `lspServerArgs` in `.noriconfig`

See the per-editor setup guides for details.
